02 · A domain's own page in a window

In version 5 every sidebar page is a window shown on a page of its own: the breadcrumb, then the window with a gutter, no agent bars (tests/look/windows/phone-v5.png, review.md row 28). Version 6 keeps that: a page a domain declares through ProvidesPages is the same window it shows in a pane tab or detached. Its route belongs to the declaring domain; Web registers it behind the page's visibility check.

Notes · Collections · Decisions — a page of the outside Notes module (vendor/acme/notes)

Opened from a nested sidebar entry three levels deep. The breadcrumb lists the navigation ancestors after the environment (new: version 5 had only project, environment and page). The window head offers Open on Home and Detach, which version 5 offered from the window's context menu. Layout: kit/ListReaderLayout with the 460 px list, PageHeader, FilterBar and Reader.

Plans · plan reader with a section from Notes in the record slot plans.reader

Version 5's outside fixture put a section into a record's inspector (acme_plan_notes, slots=("inspector.plan",)). In version 6 the Plans page declares the slot plans.reader with the context "one plan"; Notes declares a section for it. The section arrives as a deferred prop of the Plans page; Notes checks the plan through Plans' export before it reads. The section frame (34 px head on --bg-2) is the host's; the rows are Notes'.
