05 · Every state

Each window owns its states, in the version 5 forms: the shared skeleton shaped like what is coming (review.md row 32), EmptyState (14 px title, 12.5 px text, centred), WindowPlaceholder with Retry or Remove tab, the struck-through tab of a window that is gone, UpdateBand for a shell notice, and ServerCover while the server restarts. A window's state never touches its neighbours.

Window states side by side

1 First load: the deferred prop is out, the window draws its declared skeleton. 2 Empty. 3 Live update: a change arrived over the connection, the visible window's prop reloaded, the new row is tinted for 2 s and the tab count turns accent; scroll, selection and drafts stay. 4 First load failed. 5 A refresh failed: the rows already shown stay, marked with when they were read. 6 The module was removed in a deploy: the tab is struck through and the window offers Remove tab.

Shell states: connection lost, an action refused, a page that is not available

The live connection dropped: an UpdateBand-style strip under the breadcrumb says so in words; everything shown stays readable and every window keeps working by plain requests; when the connection returns, every visible window reloads once and the strip goes. The chat refused a message: the draft stays in the composer with the reason under it. The right pane is a fresh link to a page that a deploy removed (or that is hidden from this person): the same neutral page, with no hint of what was there.

Deploy: installing or removing a module restarts the server

Install and removal are a line in bootstrap/domains.php and a deploy. While the server restarts, version 5's ServerCover blurs the shell; when the new build answers, Inertia's asset version sends the tab through one full reload, and the sidebar and windows of the new set of domains appear. A tab that stays open on an old build gets Reload after a while.
