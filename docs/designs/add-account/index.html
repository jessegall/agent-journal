Add an account

The Accounts window gets one Add account button. It opens a modal of fixed size that walks through three steps: choose how to sign in, do that method's one task, and wait for the check. The body is always 404 px high and the footer always sits in the same place, so nothing jumps between steps. Signing in an existing account again stays on its row and can open the same modal at step two.

Drawn in the version 6 kit's look: Button (primary, bordered, ghost, icon; small and normal), TextField (with code and secret), Spinner, StateBadge and the colour tokens from resources/css/app.css. The kit has no modal yet; see “What a worker needs” at the end.

1 · The button on the Accounts window

One button in the page header replaces the two sign-in forms that now sit at the top of each program's section (AccountsWindow.vue lines 65–72). The empty state gets the same button. A sign-in that is still running when the window opens shows as a chip that reopens the modal where it was (from attemptToRejoin).

2 · Step one: choose how to sign in

Program choice — recommended: program first, as a switch at the top of step one. The cards below it change with the switch (3 for Claude Code, 2 for Codex), so each list fits the fixed height without scrolling, and the billing badges compare like with like. The switch opens on the program the user has fewest accounts for, or Claude Code. The alternative, one combined list of five (2c), is drawn too: it works, but it is tighter and repeats the program name in every card. A click on a card selects it; a double click or Continue moves on. Each card says how it works for the user and, as a badge, what it bills.

3 · Step two: the method's own task

Continue starts the sign-in on the host (startSignIn) at once, so the link or code is ready. While the host starts it the step shows “Starting the sign-in…” with a spinner (3a). A line under the header always says what was chosen, and Back cancels the started sign-in and returns to step one. Every field keeps its error line's room reserved, so a refusal does not move the buttons.

4 · Step three: checking, done, or what went wrong

Once the code or secret is sent (or OpenAI's page is finished), the step shows the spinner until the account appears (state checking, task 1632). Back and Close stay usable: closing never stops the check. The step ends on one of the states below. Every failure says what happened in one sentence from endedMessages (signIn.ts lines 59–67) and offers Start again (same program and method, back to step two) and Choose another way (step one).

5 · Closing, Back and reopening

The sign-in completes on the host, so closing the modal loses nothing (SignInForm.vue docblock). ✕ or Escape in step two asks once, inside the modal, so the user knows the sign-in goes on; in step three it closes without asking. Back in step two cancels the attempt (cancelSignIn). A typed code or secret is cleared on close, Back or send, as now.

What a worker needs (no code changed here)

  • A kit Modal (or Dialog) component: native <dialog>, fixed body height prop, header with step bars and ✕, footer slot, focus trap, Escape.
  • A kit Segmented switch and a selectable OptionCard (radio semantics: a role="radiogroup", arrow keys move).
  • Per-method texts: the card title, the how-it-works sentence and where-to-get-it text — best on SignInMethodData next to billingNote, keyed by program and method, since Claude Code and Codex say different things (app/Http/Data/Profiles/SignInMethodData.php; SignInMethod::billingNote).
  • A billing kind (subscription / API usage) as an enum value for the badge, instead of parsing the note.
  • AccountsWindow.vue: one header button instead of the two new-account SignInForms; SignInForm.vue split into the modal steps; the row's “Sign in again” may open the modal at step two.
  • The done state needs the new account's name: read it from the reloaded rows by the attempt's account id.
