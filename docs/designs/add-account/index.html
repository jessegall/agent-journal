Add an account

The Accounts window gets one Add account button. It opens a modal of fixed size with three steps: choose how to sign in, do that method's one task, and wait for the check. The header, the 420 px body and the footer have the same size on every step, so nothing jumps.

Drawn in the version 6 kit: Button, TextField (code, secret), Spinner and the tokens in resources/css/app.css. Blue is the interface's only accent: the progress bars, the selected card, the spinner and the done mark. Billing and status are plain grey text. Each program is marked by its product's own icon: the Claude spark for Claude Code, always in Claude's orange (#D97757) in light and dark, and the OpenAI knot for Codex, monochrome in currentColor. The marks are 16 px in rows and chosen lines, 18 px on cards, 14 px in the switch and 12 px in group headings, each set on the title's first line.

1 · The Accounts window

One list holds every account, Claude Code and Codex mixed. Each row names its program in its subtext. Rows are divided by a line and padded evenly at 12 px × 16 px, with 4 px between title and subtext, and full names and addresses wrap rather than being cut short. One header button replaces the two per-program sign-in forms (AccountsWindow.vue lines 65–72).

2 · Step one: choose how to sign in

Program choice, recommended: program first. A switch at the top of step one changes the cards below it (three for Claude Code, two for Codex), so each list fits without scrolling. The alternative, one combined list of five (2c), works too but is tighter. Clicking a card selects it, and a double click or Continue moves on. Each card says in one sentence how the method works for the user, and what it bills in grey text on the right.

Continue starts the sign-in on the host at once (startSignIn), so the link or code is ready. A line at the top of the step repeats the chosen program, method and billing. Back sits at the left of the footer, cancels the started sign-in and returns to step one. The main action sits at the right. The space under every field is held for its hint or error, so a refusal never moves the button.

4 · Step three: checking, done, or what went wrong

After the code or secret is sent, or OpenAI's page is finished, the step shows the spinner until the account appears (state checking, task 1632). Closing never stops the check. Each failure says what happened in the one sentence from endedMessages (signIn.ts lines 59–67) and offers Try again (same method) and Another way (step one). Every result has a short label as its heading and a plain sentence under it. The done mark is blue; the other marks are grey.

Step three for an API key or token: name the account

A key or token has no email to name the account by. When the check passes, step three keeps its place and asks for a name instead of showing 4b. The field opens holding a default made from the program and method (“Claude Code API key”, “Claude Code setup token”, “Codex API key”), with “ 2”, “ 3” added when that name is already in the list, all of it selected so typing replaces it. The account is already saved under that default, so closing the modal keeps it. Save renames it and moves on to 4b. A refused name shows under the field, in space already held for it, and the step stays.

6 · An account row: hover, focus and its actions

The whole row takes the --hover background when the pointer is over it. Its actions sit on the right, level with the name, and fade in on hover or when keyboard focus is inside the row. Their room is always kept, so nothing shifts when they appear. Every row action is a 24 px icon-only button with a 14 px icon. It is flush at rest (no border, no fill), takes a subtle fill on hover, and shows a tooltip on hover or keyboard focus. Each has an aria-label that says the whole action.

  • Star, on the right: filled and always shown on the default account (tooltip “Default”, aria-pressed="true"). Outlined and shown on hover for other signed-in accounts (tooltip “Make default”); a click makes that account the default. Expired and removing accounts have none.
  • Pencil, right after the name: tooltip “Rename”. It opens the rename dialog.
  • Trash can, on the right: tooltip “Remove”. It turns red on hover and opens the remove dialog.
  • Sign in again stays a small text button on an expired row, always shown. A circular-arrow icon would read as “refresh”, and this is the one thing the row needs, so it should not hide behind a tooltip.

Status stays grey text at the far right. Buttons in the wizard and in the rename and remove dialogs stay text buttons. The rows here are live: hover them.

7 · Rename dialog

A small modal in the wizard's style: 400 px wide, a fixed body, and Cancel and Save at the right of the footer. The field opens holding the current name, all of it selected, so typing replaces it. Enter saves and Escape cancels. Save stays inactive while the name is unchanged or empty. A refusal from the host shows under the field, in space already held for it, and the dialog stays open. On success the dialog closes and the row shows the new name.

8 · Remove confirmation

The dialog names the account (icon, full name, program) and says in one sentence what removal does. If work is running on the account it says how much and that the removal waits for it. What could go wrong, and how the design answers

RiskAnswer
Steps of different length make the modal jumpFixed 480 px width; a 52 px header, 420 px body and 52 px footer on every step; room under each field is held for its hint or error.
A browser error page or a sentence is pasted as the codeRefused before it reaches the program, the attempt stays live, and the field says why (3c).
The sign-in page is slow to arrive3a spinner while readChallenge polls every 2 s; Back stays usable.
The modal is closed or the page reloaded mid sign-inThe attempt keeps running; “Finish signing in” (1c) reopens it at the right step; Add account is inactive meanwhile.
The user does not see what costs moneyEvery card names its billing; the chosen line repeats it on every later step; the list's subtext keeps it.
A secret shows on screenToken and key use TextField secret (password input, new-password) and are never shown again.
The check never endsThe attempt's expiry turns it into expired, shown as 4c with Try again.
Hidden row actions can't be found by keyboard or on touchThey appear on :focus-within, so tabbing into a row shows them, and on a screen without hover (hover: none) they are always shown.
Actions appearing push the row aroundTheir space is always kept and only their opacity changes.
An account is removed by accidentA separate confirmation that names the account; focus opens on Cancel; Remove is the danger button.
Removing an account that is in useThe dialog says how many starts run on it and that removal waits; the row shows Removing until they end.
A rename is refusedThe host's sentence shows under the field in space already held for it, and the typed name stays.

What a worker needs (no project code changed)

  • A kit Modal: native <dialog>, fixed body height, header with step bars and ✕, footer slot, focus trap, Escape.
  • A kit segmented switch and a selectable option card (role="radiogroup", arrow keys move).
  • Per-program, per-method texts (card title, how it works, where to get it) and a short billing word (Subscription / Pay per use) on SignInMethodData, next to billingNote.
  • AccountsWindow.vue: one list of all rows, with the program in each row's subtext and one header button; SignInForm.vue split into the modal's steps; AccountRow's state shown as grey text.
  • The done state reads the new account's name from the reloaded rows by the attempt's account id.
  • AccountRow.vue: whole-row hover background; actions moved to the right, level with the name, with opacity on group-hover and focus-within and always shown under hover: none; every row action becomes a flush icon button (24 px, tooltip, aria-label): a pencil after the name replaces the Rename button and the inline rename form, a star replaces Make default (filled on the default), and a trash can replaces Remove. A kit IconButton with a tip prop would serve all three; Sign in again only for needs_sign_in, opening the wizard at step two.
  • Rename and remove dialogs built on the kit Modal, replacing the inline ConfirmAction for Remove.
  • RenameAccountRequest allows 200 characters (max:200) while AccountLabelInvalid and the field allow 80; the two should agree. An empty name gets Laravel's “The label field is required.”, which should say name.
