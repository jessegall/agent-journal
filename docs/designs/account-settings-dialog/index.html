The account settings dialog

The dialog the settings button on an account row opens (AccountSettingsDialog.vue, task 1691), as it is today and redesigned. It keeps the Modal's fixed frame: 480 px wide, a 52 px header, a 420 px body and a 52 px footer. Asked for in user message 13507.

1 · “Remove account”, plainlyNo trailing dots. A quiet red text button bottom left; the question that follows is its own step.
2 · Nothing grabs the name on openFocus lands on the dialog's close button, as the Modal does for any dialog; the name is not selected.
3 · Save lives inside the fieldThe name runs full width. Only a changed, non-empty name shows Save at the field's right end; Enter saves, Escape puts the name back.
4 · One tidy listDefault, the sign-in facts and the state read as two labelled groups with even rows; the body scrolls instead of clipping.

The name field, state by state

The field is always full width and 32 px tall. What sits at its right end tells the state; the line under it holds the one sentence the state needs, and is empty otherwise, so nothing below jumps.

Saving: button, blur or debounce

WayFor itAgainst it here
Save in the field, Enter saves RecommendedThe user decides when; a refusal shows where they are looking; nothing is sent while they type.A changed name is lost if they close without saving, though Save sat right there in view.
Save on blurNo click needed.Clicking Close or Remove account blurs the field and sends a rename on the way out; a refusal arrives after the dialog is gone or when the user is already doing something else.
Save after a pause (debounce)No click at all.Every save reloads the Accounts page (AccountsWindow.vue reloads on each change), which would reset the field mid-typing; half names like “Wor” get saved and refused names flash up while still typing.

Recommendation: the in-field Save with Enter. If a lost edit on Close turns out to bother users, add the blur save later, only for a non-empty changed name — the design leaves room for it.

What could go wrong

CaseWhat the design does
Empty nameNo Save; the line under says “A name is needed.” Enter does nothing.
The name typed back to what it wasCounts as unchanged: Save goes away.
The host refuses (a name in use, too long)Red edge, its message under the field, the typed name kept and Save still offered; typing again clears the red.
Escape in an edited fieldPuts the name back and keeps the dialog open; a second Escape closes it.
Close with an unsaved nameThe edit is dropped; next time the dialog opens it starts from the saved name.
The page reloads after SaveThe field shows the new saved name and “Saved” with a tick for about two seconds, then the end of the field is empty again.
Long values (an email, a workspace)Wrap anywhere inside the value column; the body scrolls.
