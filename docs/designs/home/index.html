Home — one agent across driver sessions

The visual design for doc 72 (revision 2). Home is where an owner chooses a lasting agent, reads its chat, and starts, opens, resumes or switches its driver session: the driver (Claude Code or Codex), the variant (Terminal or Headless) and the account. It is built on the current shell. The topbar (40 px) and sidebar (220 px) are unchanged. Home keeps its agent bar (54 px), its information bar (30 px) and the pane grid with draggable, resizable windows and window tabs.

What changes: the agent bar becomes the place to choose the agent and its session. It now resolves agents, not only running sessions, so an idle agent 1 is always there. The session buttons go from the top of the Chat window, sessions show up in the chat as dividers, and the composer names its destination. Starting and switching use the accounts wizard's Modal. Blue is the only accent; billing and status words are plain grey text.

1 · Home at full width

The agent bar now leads with the agent picker: the agent's number, its name and its role. Next to it are the state dot and word, and on the right the one action that fits the state. Idle: Start session (and Resume… when an earlier thread qualifies). Live: Switch… and a Stop icon. Opening a live session is simply choosing the agent; its chat and terminal are already there. The information bar lists the session's facts: number, driver, variant, account and start time. The pane grid is unchanged: Chat, Inbox and History on the left; Terminal, Runtimes and Asks on the right. Panes resize at the splitter and windows drag between them by their tabs.

2 · Choosing an agent

The picker lists the agents of the chosen environment, live or idle, by number and name, grouped as Main, Helpers and Retired. Each row says its state and its current or last driver. The environment sits at the top of the menu, and changing it chooses that environment's main agent. The search field has focus when the menu opens: type a name, move with the arrow keys, and press Enter to land on the agent with its state announced. Choosing an agent changes only which agent Home shows; the other agents keep running. The choice is kept in the URL, so a refresh or a shared link lands on the same agent with its latest state.

3 · Start a session: driver, variant, account

Start session opens the accounts wizard's Modal: 520 px wide, a fixed 500 px body, and a footer that always shows what will run. The form settles the agent's profile limits, what the host supports and which accounts may be used together. Every option that can't be chosen says why. The variant opens on this agent's own default: Terminal for the main agent, Headless for helpers. The account list shows only the chosen driver's accounts. One account is chosen for you, and expired ones say so and offer Reconnect. Picking an account here applies to this session only and never changes the installation's default. Use as default for this agent takes effect only once the start succeeds.

4 · The agent bar through every state

The agent bar always shows where the agent is: a state word plus a plain sentence under it when something needs attention. One action fits each state. A start or switch is shown while it runs and is never repeated: a second click joins the same operation. Unconfirmed steps are reconciled before anything else can start, and a failure leaves the agent idle with its history and a Retry.

5 · Switch driver, account or variant

Switch… opens the same Modal, with the current session beside the new one, the parts that change named, and the work that would be cut off. Nothing stops until Switch is pressed. The target is checked first; a refusal leaves the current session running. Closing the dialog goes back to the current session with your text intact. Changing driver or account starts a fresh thread; an earlier thread of the target can be resumed on purpose. A variant-only switch continues the same thread only when both variants support it.

6 · The chat across sessions

The chat belongs to the agent, not to a session. A divider marks each session with its driver, variant and whether it was a fresh thread or a continuation. Every reply names the session it came from, or says “session unknown” when that isn't recorded. The composer always names its destination before sending. A draft belongs to its agent: choosing another agent keeps it for when you come back. A message written against a session that has since ended keeps its text and asks where it should go.

7 · Phone width

At phone width the sidebar folds behind the menu button, and the pane grid becomes one window at a time, chosen by tabs under the agent bar. What could go wrong, and how the design answers

RiskAnswer
An owner with accounts but no session gets stuck (doc 72 §2)Home resolves agents, not sessions: agent 1 is always chosen, with Start session in the bar and in the terminal pane (1a).
Starting with the wrong driver or accountThe start card and the dialog's footer name the driver, variant and account before Start; the information bar repeats them while it runs.
An explicit account quietly changes the defaultThe account list says “for this session only”; the default stays (doc 72 §12).
A switch stops work the owner didn't mean to stopThe summary lists the running turn and the helpers, and asks about the helpers; nothing stops before Switch (5a).
Two sessions write at onceAn unconfirmed stop blocks the new start with Check again (state strip); a second click joins the same operation.
A reply is credited to the wrong sessionEach reply names its source session, or “session unknown”; dividers mark switches.
A message lands in the wrong session after a switchThe composer names the session; a stale send is held with its text and offered to the current one (6b).
Resume picks the wrong threadThreads are chosen explicitly, never the newest by default; unusable ones say why (3e).
A retired helper is started by accidentRetired agents are grouped apart, show their disposition, and have no start action (2b).
The picker is mouse-onlySearch has focus on open; arrows, Enter and Esc; the chosen agent's state is announced (2a).

What changes in the frontend (no project code changed here)

  • resources/js/components/home/AgentBar.vue: from “running session only” (its line 4) to the agent picker, the state word, a plain sentence when needed, and one action per state (Start session, Resume…, Switch…, Stop, Retry, Check again).
  • resources/js/components/home/InformationBar.vue: the lead stays the agent; add the session number, driver · variant, account and start or end time. The layouts button stays.
  • domain/Chat/resources/js/ChatPane.vue: remove the session button row (lines 77–103); add session dividers, the source session on each reply, the composer's destination line, and the held-message notice. Drafts are keyed by user, environment and agent (doc 72 §12).
  • The terminal window shows the start card when the agent is idle, and joins the existing runtime when it's live.
  • New: an agent picker menu (kit MenuList look), and Start, Resume and Switch dialogs on the kit Modal from the accounts design; on phones, a bottom sheet.
  • Home's data: HomeData returns the agents (idle included), the chosen agent, its live session, eligible actions with reasons, accounts by driver and resumable threads (doc 72 §12).
  • Topbar, sidebar, the pane grid, window tabs, dragging and resizing are unchanged. At phone width the pane grid shows one window at a time behind tabs.
