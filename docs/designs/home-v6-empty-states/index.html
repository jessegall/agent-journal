Page and the after frame

When a list page has no rows yet, it does not split into a list and a reader. Everything under the page header is one region, and one empty state sits in its middle: a muted icon for the subject, a short title, one sentence on what the thing is for, and the action that makes the first one. The page header keeps its title, its count of 0 and its own action. This extends Home, version 6 · round 4 and uses its tokens and components unchanged.

Rules for builders

When it showsOnly when the page has no rows at all. The page draws .emptyfull in place of .pgbody, so there is no list column, no divider and no "Nothing selected" reader.
Centred in the whole content areaCentred both ways in everything under the page header, not in the old list column. On a narrow window it stays centred and the text wraps.
Width and typeThe text is at most 360 px wide. Title in --text-2, weight 500; sentence in --text-3; both at --text-empty. The icon is 20 px in --text-4 on a 40 px tile.
WordsTitle: "No things yet". One plain sentence on what the thing is for. The action uses the header's own words, such as Add account or New plan, and does the same thing.
The header staysTitle, count 0 and the header's action stay as they are, so the page looks the same before and after the first row.
A filter with no matches is differentWhen rows exist but a filter or search hides them all, the split stays. The list column says "No matches" with the filter named, and offers Clear filter. The reader keeps its own state. Never show the full empty state for this.
After the first oneWhen the first row is made, the split comes back with that row selected and open in the reader, and the count goes to 1.
Loading is not emptyWhile the rows are still loading, show nothing in the region. Show the empty state only once the page knows there are no rows.

Profiles: the project has no route or form to make a profile yet (routes/profiles/web.php only starts and switches them). New profile needs that flow before it can work.
